# 기술 구조

제품 동작·제약·수용 기준은 루트 [SPEC.md](../SPEC.md)를 따른다. 이 문서는 구현 방식과 선택 이유를 설명한다.

## 상태 엔진

`src/domain/cube/cube.ts`는 브라우저에 의존하지 않는 순수 TypeScript 모듈이다. 54개 스티커 각각의 고유 ID, 정수 3D 위치, 면 법선, 색상을 저장한다. 면 회전은 해당 층의 위치와 법선을 동일한 축으로 90° 회전하고 정수로 확정한다.

기본 좌표는 +X 오른쪽, +Y 위, +Z 앞이다. 면 밖에서 본 시계 회전은 바깥쪽 법선에 대해 -90°다. 전체 수평 회전의 오른쪽 입력은 `Y, turns: 1`(-90°), 왼쪽 입력은 `Y, turns: -1`(+90°)에 연결한다. 모든 조각·센터를 Y축으로 회전하므로 이후 F/R/L/B는 새 전면 기준으로 자연스럽게 작동한다.

프리셋은 완료 상태에 합법적인 수순을 적용해 생성한다. 십자가 프리셋은 D 엣지를 보존하는 옆면/U/역옆면 수순, 1·2층 프리셋은 U와 Sune 수순을 사용한다. 시작 수순을 함께 반환하여 재현·역수순 검증이 가능하다.

## 두 그림의 표현

`CubeView.tsx`는 26개 조각의 표면과 스티커를 3D에서 SVG 좌표로 직교 투영한다. 큰 그림의 관찰 방향과 정확히 반대 방향에서 작은 그림을 관찰하되, 위아래를 뒤집어 B/L/D가 보이게 한다. 앞면의 투영 면적이 옆면보다 크도록 관찰 각도를 고정한다.

회전 중에는 움직이는 층의 조각과 법선을 연속 회전하고, 관찰자를 향한 표면만 깊이 순서로 그린다. 두 SVG는 같은 상태·명령·진행률을 받는다. SVG를 사용하므로 사진 자산이나 WebGL 의존성이 없다. 참조 이미지 파일은 삭제해도 무방하다.

SVG 센터의 글자는 원본 큐브 기준 F/R/U 또는 B/L/D다. 애니메이션 중에는 글자를 숨기고 완료 경계에서 새 기준으로 다시 표시한다.

## 세션과 입력

`session.ts`는 상태, 입력 큐, 진행률, 실행 이력, 선택한 프리셋과 시작 수순을 관리하는 reducer다. 입력 큐는 최대 20수다. 현재 명령이 완료되는 순간 논리 상태와 이력을 함께 갱신하고 다음 명령으로 진행한다.

`App.tsx`는 키보드·터치 입력을 동일한 명령으로 변환하고 `requestAnimationFrame`으로 진행률을 전달한다. 명령 객체를 함께 전달하므로 프리셋 변경 후 도착한 이전 프레임은 무시한다. 언마운트·명령 변경 시 예약된 프레임을 취소한다.

큐브 회전과 전체 수평 회전 모두 되돌릴 수 있다. 프리셋 변경은 대기 큐와 이력을 초기화한다. 속도 선택은 현재 회전의 애니메이션을 다시 시작할 수 있으나 논리 상태는 완료 시 한 번만 반영된다.

## 검증

- `tests/cube.test.ts`: 알려진 회전 방향, 가역성, 전체 회전 후 기준 면, 스티커 위치 보존, 각 프리셋 100개 표본의 제약과 역수순 복원.
- `tests/session.test.ts`: 명령 순서, 중복 프레임 방지, 초기화 후 오래된 프레임 무시, 큐 제한, 되돌리기.
- `tests/browser/simulator.spec.ts`: 키보드·화면 버튼, 실제 SVG 변경, 프리셋, 애니메이션 중 초기화, 네 화면 너비의 두 그림 표시.
- CI에서 타입·린트·포맷·단위 테스트·빌드·Chromium 검증을 실행한다.

실제 iOS/Android 성능은 별도 검증 항목이다. 저장·백엔드·외부 분석 도구·사진 요청은 없다.
